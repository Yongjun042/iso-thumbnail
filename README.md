# iso-thumbnail

Blu-ray와 DVD `.iso` 이미지의 썸네일을 Windows 탐색기에 보여 주는 셸 확장(썸네일 핸들러)입니다.
Blu-ray는 디스크 안에 들어 있는 아트워크(`BDMV/META/DL/*.jpg`)를, 그것이 없으면 디스크의 탑 메뉴 화면(버튼 포함)이나
본편 영상의 한 장면을 쓰고, DVD는 재킷 그림(`JACKET_P`)이나 디스크의 메뉴 화면을, 그것도 없으면 본편 영상의 한 장면을 씁니다.
빌드 결과물은 `IsoPreview.dll`과 `isopreview-cli.exe`입니다.

- Rust로 작성한 네이티브 DLL 하나(약 580 KB)로 동작하며, 별도의 런타임이 필요 없습니다.
- 이미지 전체를 읽지 않고 필요한 섹터만 읽기 때문에, 수십 GB짜리 이미지라도 1 ms 안팎에 아트워크를 찾습니다.
- UDF 1.02 ~ 2.60(메타데이터 파티션, 스페어러블 파티션, 가상 파티션/VAT 포함)과 ISO 9660 + Joliet를 읽습니다.
- DVD 영상과 Blu-ray의 MPEG-2 영상은 Rust로 직접 작성한 MPEG-1/MPEG-2 인트라 프레임 디코더로 풀기 때문에, 설치된
  코덱이나 Media Foundation이 필요 없습니다. 이미지 전체가 아니라 샘플 지점 근처의 수 MiB만 읽습니다.
- Blu-ray의 H.264, HEVC(UHD), VC-1 영상은 Windows에 들어 있는 Media Foundation 디코더로 키 프레임 하나만 풀고,
  HDR(HDR10, Dolby Vision 기본 계층)은 SDR로 톤 매핑합니다. 디스크 하나에 보통 수십~수백 ms가 걸리고, 어두운 장면이
  이어지는 UHD 디스크도 1초 남짓에서 멈춥니다.
- 시스템 전체 설치(HKLM)와 현재 사용자 설치(HKCU) 모두 셸이 핸들러를 격리된 COM 대리 프로세스(`dllhost.exe`)에서 실행하므로,
  문제가 생겨도 탐색기 자체에는 영향이 없습니다.
- 신뢰할 수 없는 파일을 파싱하는 코드는 모두 경계 검사를 거치며, 패닉은 COM 경계에서 오류 코드로 바뀝니다.

## 썸네일을 찾는 순서

1. `BDMV/META/DL/*.jpg` : Blu-ray Disc Library 썸네일입니다. 여러 개가 있으면 파일 이름의 `WxH`가 가장 큰 것을, 그것도 없으면 파일 크기가 가장 큰 것을 고릅니다.
2. `BDMV/META/TN/*.jpg` : 트랙 이름 메타데이터의 썸네일입니다.
3. `JACKET_P/J00___5L.MP2` (없으면 `5M`, `5S`) : DVD-Video의 재킷 그림입니다. MPEG-2 정지 화상이며 주로 일본 DVD에 들어 있습니다.
4. 루트 폴더의 `folder`, `cover`, `poster`, `thumbnail`, `thumb`, `front`, `artwork` + `.jpg/.jpeg/.png/.bmp/.gif` : 일반 데이터 디스크용 대체 경로입니다.
5. DVD 메뉴 화면 : IFO 파일의 메뉴 표(PGCI_UT)가 가리키는 위치에서 다음 메뉴를 차례로 디코딩합니다.
   - 본편 타이틀 세트의 루트 메뉴(메인 메뉴, `VTS_nn_0.VOB`)
   - 비디오 매니저의 타이틀 메뉴(`VIDEO_TS.VOB`), 또는 타이틀 메뉴가 `JumpSS`로 넘겨주는 타이틀 세트의 루트 메뉴
   - 나머지 타이틀 세트의 루트 메뉴(`VTS_01`부터, 그다음은 타이틀 크기 순)

   셀 없이 명령만 가진 입구 PGC(`LinkPGCN`으로 실제 메뉴 PGC로 넘기는 라우터)는 몇 단계까지 따라갑니다. 메뉴마다 첫 셀의
   시작, 마지막 셀의 시작(인트로 셀 다음의 반복 구간), 첫 셀의 마지막 VOBU(움직이는 메뉴의 도입 애니메이션이 끝난 화면)를
   차례로 봅니다. VOB 밖을 가리키는 셀은 버리고 다음 언어 단위를 보며, IFO가 손상되었으면 백업(`.BUP`)을 읽습니다.
6. DVD 본편의 한 장면 : 쓸 만한 메뉴 화면이 없으면, `VIDEO_TS`에서 VOB 데이터가 가장 많은 타이틀 세트
   (`VTS_nn_1.VOB` ~ `VTS_nn_9.VOB`)를 본편으로 보고 전체 길이의 25%, 40%, 15%, 55%, 70% 지점과 마지막으로 처음 지점을
   차례로 살펴 각 지점 뒤의 첫 I 프레임을 디코딩합니다. 본편에서 쓸 만한 장면을 얻지 못하면 남은 시도 횟수만큼
   두 번째로 큰 타이틀 세트도 봅니다(본편이 스크램블되어 있으면 시도를 쓰지 않으므로 여섯 지점까지 봅니다).
7. IFO 정보 없이 메뉴 VOB(`VIDEO_TS.VOB`, `VTS_nn_0.VOB`)의 첫 화면 : IFO로 찾은 메뉴에서 쓸 수 있는 화면을 하나도
   얻지 못했고 쓸 만한 화면도 없을 때만 씁니다. `VIDEO_TS.VOB`의 맨 앞은 경고문이나 제작사 로고인 경우가 많아서, IFO로 찾은 메뉴가
   어둡더라도 그쪽을 남깁니다.
8. Blu-ray 탑 메뉴 화면 : 아트워크가 없는 Blu-ray는 먼저 `BDMV/index.bdmv`에서 탑 메뉴로 실행되는 객체를 찾습니다.
   - HDMV 메뉴(무비 오브젝트)는 `BDMV/MovieObject.bdmv`의 내비게이션 명령을 따라가며 메뉴가 재생하는 플레이리스트를
     찾습니다. `PlayPL` 계열 명령의 플레이리스트를 나오는 순서대로 모으고(`PlayPLatPlayItem`과 `PlayPLatMark`는 지정한
     재생 항목이나 마크에서 시작합니다), `GoTo`, `JumpObject`, `CallObject`, `JumpTitle`, `CallTitle`을 따라가며(타이틀
     0은 탑 메뉴, 0xFFFF는 첫 재생 객체입니다), 상수를 넣은 범용 레지스터(`Move`)도 추적합니다. 비교 명령은 참과 거짓
     양쪽 경로를 모두 살펴봅니다(참인 경로가 먼저입니다). `SetButtonPage`로 고른 버튼은 페이지에 기본 선택 버튼이 없을
     때 선택 상태로 그립니다.
   - BD-J 메뉴는 자바 코드가 화면을 그리므로 따라갈 수 없고, BD-J 객체(`BDMV/BDJO/nnnnn.bdjo`)가 스스로 시작하도록
     지정한 첫 플레이리스트(autostart)가 있을 때만 그것을 씁니다.
   - 플레이리스트(`BDMV/PLAYLIST/nnnnn.mpls`)에서 재생이 시작되는 재생 항목의 클립과 IN/OUT 시각을 읽고, 그 구간에
     있는 키 프레임을 처음과 중간 위치에서 디코딩합니다(움직이는 메뉴는 페이드 인으로 시작할 수 있습니다). 그림이
     하나뿐인 정지 메뉴는 클립 끝에서 그 그림이 끝난 것으로 봅니다(정렬 단위로 끝나는 클립에서만이며, MPEG-2는 모든
     매크로블록이 디코딩될 때만 씁니다. 그래서 중간에 잘린 사본의 마지막 그림은 회색 띠가 낀 채로 쓰이지 않습니다). HDMV 메뉴에는 반드시 버튼이 있으므로, 인터랙티브
     그래픽(IG) 스트림이 없는 플레이리스트(인트로, 예고편)나 팝업 메뉴만 있는 플레이리스트(팝업 메뉴가 딸린 본편)는
     메뉴로 보지 않고 건너뜁니다. 팝업 메뉴인지는 첫 구성 세그먼트에서 알 수 있으므로 거기서 읽기를 멈추며, 이런
     플레이리스트는 시도 횟수에 넣지 않습니다.
   - 클립에 함께 다중화된 IG 스트림에서 첫 디스플레이 세트(구성, 팔레트, 런 길이 부호화된 버튼 그림)를 읽어, 첫
     페이지의 버튼을 배경 화면 위에 그립니다. 플레이어는 재생 항목을 IN 시각 직전의 진입점부터 읽고,
     libbluray처럼 IN 시각 이전에 표시되는 그래픽은 버리고 그 뒤의 그래픽만 씁니다. 디스플레이 세트는 표시 시각보다
     앞에 다중화되므로, 그 진입점보다 1 MiB 앞에서부터(재생 항목이 클립의 첫 진입점에서 시작하면 클립의 처음부터)
     읽으면서 같은 시각 기준으로 거릅니다. libbluray처럼 BOG마다 유효한 버튼 하나를 그리고, 기본 선택
     버튼은 선택 상태로, 나머지는 보통 상태로 그립니다. 한 번만 재생되는 버튼 애니메이션은 끝난 뒤의 마지막 그림으로,
     반복되는 애니메이션과 애니메이션이 아닌 상태는 첫 그림으로 그리므로 메뉴가 자리 잡은 모습과 같습니다.
   - 탐색 파일이 손상되었으면 `BDMV/BACKUP`의 사본을 읽습니다.
9. Blu-ray 본편의 한 장면 : 쓸 만한 메뉴 화면이 없으면(메뉴 단계가 시간을 다 썼더라도 본편에서 장면을 하나 얻을
   때까지는 시간 제한을 두지 않습니다)
   `BDMV/STREAM`에서 가장 큰 클립(`nnnnn.m2ts`, 1 MiB 이상)을 본편으로
   봅니다. 실제 디스크에서는 이것이 메인 플레이리스트의 가장 긴 재생 항목과 같으며, 가짜 플레이리스트가 수백 개인 디스크에서도
   플레이리스트를 해석하지 않고 찾을 수 있습니다. 클립 정보 파일(`BDMV/CLIPINF/nnnnn.clpi`, 손상되었으면 `BDMV/BACKUP`의 사본)의
   EP_map에는 모든 I 프레임의 위치와 대략의 크기가 들어 있으므로, 목록의 25%, 40%, 15%, 55%, 70% 위치에 있는 I 프레임을
   스트림을 훑지 않고 바로 읽어 디코딩합니다. 3D 디스크의 종속 뷰(오른쪽 눈) 클립은 혼자 디코딩할 수 없으므로 건너뛰며,
   본편에서 쓸 만한 장면을 얻지 못하면 남은 시도 횟수만큼 다음으로 큰 클립(최대 세 개)도 봅니다.
   - MPEG-2는 자체 디코더로, H.264, HEVC, VC-1은 Windows의 Media Foundation 디코더로 풉니다.
   - HDR10과 Dolby Vision(기본 계층)은 ITU-R BT.2390 방식으로 SDR로 톤 매핑하고 BT.2020 색역을 BT.709로 바꿉니다.
     UHD 영상은 가로 1920 이하로 줄입니다.

5~9단계에서는 거의 검거나 하얗거나 단조로운 화면(페이드, 로고, 제목 화면)을 건너뛰고, 위아래나 좌우에 짝을 이룬
검은 띠는 잘라 냅니다. 쓸 만한 화면이 하나도 없으면 그중 가장 나은 화면을 씁니다.

어느 단계에서든 비어 있거나 상한을 넘거나 읽을 수 없는 파일은 건너뛰고 다음 후보를 봅니다.
아무것도 없으면 핸들러가 실패를 돌려주고, 탐색기는 평소처럼 기본 `.iso` 아이콘을 보여 줍니다.
CSS로 암호화된 상태 그대로 만든 DVD 이미지는 영상을 복호화하지 않으므로 타이틀에서 장면을 만들지 못합니다.
그런 이미지에서도 재킷 그림과 루트 커버는 그대로 쓰이고, 메뉴 VOB가 암호화되어 있지 않으면 메뉴 화면이 썸네일이
됩니다. IFO 정보가 없어 7단계까지 가면 경고문이나 로고 화면일 수 있습니다. AACS로 암호화된 상태 그대로 만든
Blu-ray 이미지도 마찬가지로 영상 장면을 만들지 않지만, 암호화되지 않는 `BDMV/META`의 아트워크는 그대로 쓰입니다.

## 빌드

Rust 1.82 이상과 Visual Studio Build Tools(MSVC 링커)가 필요합니다.

```bash
cargo build --release
```

결과물은 `target\release\IsoPreview.dll`(셸 확장)과 `target\release\isopreview-cli.exe`(설치 및 진단 도구)입니다.

## 설치

### 현재 사용자만 (관리자 권한 불필요)

```bash
scripts\install.cmd
```

두 파일을 `%LocalAppData%\Programs\IsoPreview`에 복사하고 `HKEY_CURRENT_USER`에 핸들러를 등록합니다.
시스템 전체 설치와 마찬가지로 핸들러는 탐색기가 아니라 셸의 격리된 대리 프로세스(`dllhost.exe`)에서 실행되며,
이 대리 프로세스는 HKCU 등록도 찾습니다. `isopreview-cli.exe`로 등록하지 못하면(백신이 서명 없는 실행 파일을
막는 경우 등) `regsvr32 /n /i:user`로 다시 등록합니다.

### 모든 사용자

관리자 권한으로 연 프롬프트에서 실행합니다. `%ProgramFiles%\IsoPreview`에 복사하고 `HKEY_LOCAL_MACHINE`에 등록합니다.

```bash
scripts\install-machine.cmd
```

### regsvr32로 직접 등록

```bash
regsvr32 /n /i:user IsoPreview.dll
```

위 명령은 현재 사용자에게만 등록합니다. `regsvr32 IsoPreview.dll`은 관리자 권한이면 시스템 전체에, 아니면 현재 사용자에게 등록합니다.

### 설치 후 썸네일이 바로 보이지 않을 때

탐색기는 파일 형식별 핸들러 정보와 썸네일을 캐시합니다. 설치 전에 이미 본 `.iso` 파일이 계속 아이콘으로 보이면
`scripts\restart-explorer.cmd`로 탐색기를 다시 시작하고, 그래도 안 되면 `scripts\clear-thumbnail-cache.cmd`로
썸네일 캐시를 지웁니다. 탐색기 옵션의 "아이콘은 항상 표시하고 미리 보기는 표시 안 함"이 꺼져 있어야 합니다.

설치와 제거는 일반 명령 프롬프트나 Windows 터미널에서 실행하세요. Claude 데스크톱 앱처럼 MSIX로 패키징된 앱 안의
터미널에서 실행하면 `HKCU\Software\Classes`에 쓴 등록이 그 앱 전용 가상 레지스트리에 기록되어 탐색기가 보지 못합니다.
같은 앱 안에서 `reg query`로 확인하면 등록이 보이기 때문에 설치가 된 것처럼 보이니 주의하세요.

## 제거

```bash
scripts\uninstall.cmd
```

시스템 전체 설치는 관리자 프롬프트에서 `scripts\uninstall-machine.cmd`를 실행합니다.
`isopreview-cli --uninstall`이나 `regsvr32 /u /n /i:user IsoPreview.dll`로도 등록을 해제할 수 있습니다.
제거 스크립트는 찾을 수 있는 CLI를 차례로 실행하고, 모두 실패하면 `regsvr32`로 해제합니다. 등록을 해제하지 못하면
파일을 지우지 않고 오류로 끝나므로, 등록만 남고 DLL이 사라지는 일은 없습니다.
썸네일 대리 프로세스(`dllhost.exe`)가 DLL을 아직 물고 있으면 파일 삭제가 잠시 미뤄질 수 있습니다. 대리 프로세스는 한동안
쓰이지 않으면 스스로 끝나므로 조금 뒤에 다시 지우면 됩니다. 이전 버전으로 설치해서 탐색기가 DLL을 직접 물고 있다면
탐색기를 다시 시작하세요.

## 명령줄 도구로 확인하기

```bash
isopreview-cli movie.iso
```

파서만 실행해서 어느 파일 시스템(UDF 2.50 등)에서 어떤 아트워크를 골랐는지, 읽기 횟수와 소요 시간을 출력합니다.
디스크에 들어 있던 그림 파일은 그대로 `movie.thumb.jpg`(파일 서명에 따라 `.png`, `.gif`, `.bmp`)로 저장하고,
DVD에서 디코딩한 재킷 그림이나 장면은 화면 비율을 보정한 크기의 PNG(`movie.thumb.png`)로 저장합니다.

```bash
isopreview-cli movie.iso --mode com --size 256
```

`IsoPreview.dll`을 COM 객체로 직접 로드해서 `IThumbnailProvider::GetThumbnail`을 호출하고 결과를 PNG로 저장합니다.
등록하지 않아도 동작하므로 DLL 자체를 시험할 때 씁니다.

```bash
isopreview-cli movie.iso --mode shell --size 256
```

등록된 핸들러를 Windows 셸(`IShellItemImageFactory`)을 통해 호출합니다. 탐색기가 하는 것과 같은 경로이므로
등록 상태까지 함께 확인할 수 있습니다.

`isopreview-cli --install`, `--install-machine`, `--uninstall`은 설치 스크립트가 내부적으로 쓰는 등록 명령입니다.
`--uninstall`은 현재 사용자와 시스템 전체 등록을 모두 해제하며, 하나라도 해제하지 못하면(관리자 권한 없이 시스템 전체
등록을 만난 경우 포함) 종료 코드 1을 돌려줍니다.

## 동작 원리

1. 탐색기가 `.iso` 파일의 썸네일 핸들러(CLSID `{C767266A-4032-4099-9A92-F91D1FE98122}`)를 찾아 파일의 `IStream`을 넘겨줍니다.
2. 핸들러는 섹터 256의 Anchor Volume Descriptor Pointer에서 시작해 볼륨 디스크립터, 파티션 맵, File Set Descriptor,
   루트 디렉터리를 차례로 읽고 `BDMV/META/DL`까지 내려갑니다. UDF가 없으면 ISO 9660(Joliet 우선)으로 다시 시도합니다.
3. 고른 파일을 파일 서명에 맞는 Windows 기본 디코더(JPEG, PNG, GIF, BMP)로 디코딩하고, 요청받은 크기(`cx`)를
   넘지 않게 축소한 뒤 32비트 DIB(`HBITMAP`)로 돌려줍니다. 원본보다 키우지는 않습니다.
4. DVD는 먼저 IFO 파일에서 헤더 한 섹터와 메뉴 표만 읽어 메뉴가 있는 섹터를 알아냅니다. 메뉴 표의 길이 필드는
   참고만 하고 파일에 있는 만큼(최대 256 KiB) 읽습니다. 그다음 VOB 파일(MPEG
   프로그램 스트림)에서 비디오 패킷만 뽑아 내고, 시퀀스 헤더 뒤의 첫 I 프레임 하나만 자체 디코더로 풉니다. 디코딩한 YCbCr 4:2:0 영상은 스트림이 알려 주는 색 행렬(BT.601 또는 BT.709)로 RGB로 바꾸고, 화면 비율
   (4:3, 16:9)에 맞게 가로를 보정한 크기로 축소합니다.
5. Blu-ray는 클립 정보 파일의 EP_map이 가리키는 소스 패킷(192바이트 단위)에서 I 프레임 크기만큼만 읽어, 비디오 PID의
   첫 PES 패킷 하나를 꺼냅니다. Blu-ray에서는 PES 패킷 하나에 키 프레임의 액세스 유닛이 파라미터 세트와 함께 들어
   있습니다(인터레이스 영상은 두 필드). 패킷은 다음 패킷이 시작되거나 헤더에 적힌 길이(`PES_packet_length`)를 채우면
   끝난 것으로 보며, 사이에 오디오 패킷이 많아 그 안에서 끝나지 않으면 읽은 범위를 두 배씩 늘려 이어 읽습니다.
   H.264/HEVC/VC-1은 헤더(SPS, PPS, VPS, 시퀀스 헤더)를 먼저 검사한 뒤 Media Foundation 디코더에 그 액세스 유닛 하나만
   넣고 스트림 끝을 알려 프레임을 받아 냅니다. 디코더 출력(NV12, 10비트는 P010)은 표시 영역만큼 잘라 RGB로 바꿉니다.
6. Blu-ray 메뉴의 IG 스트림은 세그먼트(팔레트 PDS, 그림 ODS, 구성 ICS, 끝 END)로 이루어져 있으며, 여러 세그먼트로
   나뉜 구성과 그림은 다시 이어 붙입니다. 버튼 그림은 팔레트(Y, Cr, Cb, 투명도)로 그래픽 평면에 그린 뒤, 디코딩한
   YCbCr 4:2:0 화면에 투명도대로 섞습니다. 평면 크기가 화면과 다르면 화면 크기에 맞추고, 팔레트는 HD 메뉴는 BT.709,
   SD 메뉴는 BT.601로 보고 화면의 색 행렬로 바꿉니다.

## 보안과 성능 설계

핸들러는 사용자가 내려받은 임의의 파일을 파싱합니다. 탐색기에서는 격리된 대리 프로세스에서 실행되지만, 셸 API로
핸들러를 자기 프로세스 안에 직접 불러오는 프로그램도 있습니다. 그래서 다음과 같은 상한을 두고, 모든 파싱은 경계 검사를
거치며 정수 오버플로도 릴리스 빌드에서 검사합니다.

| 이미지에 대한 읽기 횟수 | 256회 | 하드 디스크나 네트워크 공유에서는 탐색(seek) 횟수가 시간을 좌우합니다. 익스텐트를 흩어 놓은 조작된 이미지는 이 상한까지 읽게 만들 수 있으며, 캐시가 비어 있는 하드 디스크에서는 썸네일 하나에 2~3초가 걸립니다. 정상 디스크도 느린 매체에서는 비슷하게 걸리므로, 시간 마감을 두어 정상 썸네일을 잃는 대신 이 상한으로 막습니다. |

- 패닉은 `IThumbnailProvider::GetThumbnail` 경계에서 붙잡아 `E_FAIL`로 바꾸므로 핸들러를 부른 프로세스로 전파되지 않습니다.

  확장자만 `.jpg`인 TIFF, JPEG XR, RAW 같은 데이터가 설치된 아무 코덱에나 넘어가고, 일부 코덱은 위의 픽셀 상한과
  무관하게 수백 MB를 할당합니다.
- 핸들러 객체는 `ThreadingModel=Apartment`에 맞게 agile로 동작하지 않으므로, 다른 아파트에서의 호출은 COM이 직렬화합니다.
  한 번 초기화된 객체의 재초기화는 `ERROR_ALREADY_INITIALIZED`로 거부합니다.
- `DllCanUnloadNow`는 살아 있는 핸들러와 클래스 팩토리, `LockServer` 잠금이 모두 없어진 뒤에만 언로드를 허락합니다.
- C 런타임을 정적으로 링크해서 `VCRUNTIME140.dll`(VC++ 재배포 패키지)이 없는 PC에서도 로드됩니다.
- JPEG는 WIC 디코더의 `IWICBitmapSourceTransform`을 통해 필요한 크기에 가까운 축소 해상도로 바로 디코딩하고,
  PNG 등 축소 디코딩을 지원하지 않는 형식만 전체 디코딩 후 축소합니다.
- 디렉터리 항목 순회는 필요한 항목을 찾는 즉시 멈추고, 루트 디렉터리는 한 번만 읽어서 `BDMV`와 루트 커버 후보를 함께 찾습니다.
- 후보를 비교할 때는 파일 엔트리의 크기 필드만 읽고, 할당 디스크립터는 실제로 읽을 파일에 대해서만 해석합니다.
  메타데이터 파티션의 블록 위치는 이진 탐색으로 찾습니다.
- 이미지를 한 번 읽을 때마다 32 KiB 단위로 캐시하므로, 실제 Blu-ray 구조를 따라가는 데 필요한 읽기는 10회 안팎입니다.
- UDF 앵커는 보통 위치(2048바이트 블록의 섹터 256)에서 먼저 찾고, 없을 때는 볼륨 인식 시퀀스(바이트 32768부터)에 UDF
  표시(NSR02/NSR03)가 있을 때만 다른 블록 크기와 이미지 끝의 위치를 찾습니다. 이 영역은 이어지는 ISO 9660 단계가 어차피
  읽으므로 읽기가 늘지 않습니다. 그래서 썸네일이 없는 가장 흔한 경우인 ISO 9660 전용 데이터 디스크(리눅스 배포판 ISO 등)는
  이미지 곳곳을 7번 읽던 것을 2번 읽고 끝냅니다.
- 디코딩한 화면은 셸이 요청한 썸네일 크기의 2배 이상이 남는 가장 큰 정수 배율로 Y'CbCr 단계에서 먼저 줄인 뒤 RGB로
  바꿉니다. HDR 톤 매핑처럼 화소마다 변환하는 화면은 그 변환 전에 줄입니다. 256 px 썸네일 기준으로 MPEG-2 Blu-ray는
  31 ms에서 20 ms로, UHD HDR10은 303 ms에서 217 ms로 줄었습니다. 메뉴 버튼은 원래 크기의 화면 위에 그린 뒤에 줄입니다.
  명령줄 도구의 추출 모드는 진단용으로 원래 크기를 그대로 저장합니다.
- `tests/budgets.rs`는 전역 할당자로 할당량을 세어, 조작된 이미지가 쓰는 메모리의 상한을 검사합니다(가상 파티션 맵 15개를
  선언한 UDF 이미지도 24 MiB 안에서 끝나는지 등).
- `tests/parsers.rs`는 합성 ISO 9660/UDF 이미지(메타데이터 파티션 포함)로 정상 경로, Indirect Entry, 깨진 루트 커버를 건너뛰는
  경우와 잘린 이미지, 무작위로 손상된 이미지를 검사합니다.
- MPEG 디코더의 비트스트림 읽기는 모두 경계 검사를 거칩니다. 손상된 슬라이스는 회색으로 메우고 다음 슬라이스부터 이어 가며,
  매크로블록의 10%를 넘게 메운 장면은 쓰지 않습니다.
- 비디오 패킷의 CSS 스크램블 표시가 켜져 있으면 그 패킷은 복호화하지 않고 버립니다. VOB는 팩 단위로 역다중화하므로,
  버린 패킷 앞에서 이미 끝난 그림은 그대로 쓰고, 그 패킷에 걸쳐 있던 데이터는 앞뒤를 한 그림으로 이어 붙이지 않도록
  버립니다. 드문드문 스크램블된 타이틀에서도 구멍 사이의 온전한 그림은 쓸 수 있습니다.
- VOB 끝에서 끝나는 마지막 그림은 잘린 패킷이 없고 모든 매크로블록이 디코딩될 때만 씁니다. 잘린 VOB의 마지막 그림이
  회색 줄이 낀 채로 썸네일이 되지 않게 하기 위해서입니다.
- DVD는 UDF와 ISO 9660 양쪽에 같은 파일을 담고 있으므로, UDF 쪽에서 썸네일을 찾지 못해 ISO 9660 쪽을 다시 볼 때는
  비용이 큰 DVD 탐색(재킷 그림, 메뉴, 장면)을 반복하지 않습니다. 단, UDF 쪽에서 타이틀 VOB의 비디오 패킷을 실제로 하나도
  읽지 못했다면(파일 엔트리나 할당 디스크립터가 손상된 경우) 메뉴를 읽었더라도 ISO 9660 쪽에서 다시 찾습니다.
  Blu-ray 장면 탐색도 같은 규칙을 따르며, `VIDEO_TS`와 `BDMV`가 함께 있는 디스크는 DVD 쪽에서 아무것도 얻지 못하면
  같은 쪽에서 Blu-ray 장면을 찾습니다.
- Blu-ray의 AACS 암호화는 풀지 않습니다. 읽은 범위의 정렬 단위(6144바이트) 첫 소스 패킷에 복사 제어 비트가 켜져 있거나
  TS 패킷에 스크램블 표시가 있으면 그 디스크의 장면 탐색을 그만둡니다.
- 디코더는 Media Foundation에 등록된 것(H.264와 VC-1은 Windows 기본 디코더, HEVC는 Store의 확장)을 쓰며, 메모리 안전한
  코드가 아니므로 신뢰할 수 없는 데이터를 넘기기 전에 디코더에 갈 패킷 전체를 직접 해석합니다. 첫 그림이 키 프레임(H.264는
  I 슬라이스, HEVC는 IDR/CRA/BLA, VC-1은 I 프레임)인지, 패킷 안의 모든 SPS가 잘라 내기 전의 부호화 크기로 4096×2304
  이하이고 4:2:0 8/10비트(H.264는 루마와 크로마 모두 8비트)인지, 금지 비트가 켜진 NAL 유닛이나 HEVC 확장 계층이 없는지
  확인합니다. VC-1은 진입점 헤더의 부호화 크기가 시퀀스 헤더의 최대 크기를 넘지 않는지와 헤더 길이(512바이트)도
  봅니다. 디코더는 확인한 형식으로 설정하고 작업 스레드 1개와 썸네일 모드를 요청하며, 출력 형식을 정하지 못하면
  스트리밍을 시작하지 않습니다(HEVC 디코더는 출력 형식 없이 시작하면 비정상 종료합니다). 입력이 거절되면 다시 넣지 않고
  그만둡니다. 출력 버퍼는 선언한 크기, 줄 간격(음수는 거절), 표시 영역이 버퍼 안에 들어가는지 확인한 뒤에만 읽습니다.
- Media Foundation은 Windows 디코더가 필요한 첫 클립에서야 `MFStartup(MFSTARTUP_LITE)`로 시작하고, 썸네일을 만든 뒤
  `MFShutdown`으로 끝냅니다. 아트워크가 있는 디스크와 DVD에서는 시작하지 않습니다.
- Windows의 HEVC 디코더는 UHD 10비트 키 프레임 하나를 디코딩하는 약 0.3초 동안 약 300 MiB를 예약(commit)합니다(실제
  사용 메모리는 약 150 MiB). 탐색기의 썸네일 대리 프로세스는 추출 요청을 하나씩 처리하므로 이 메모리가 요청 수만큼 쌓이지
  않습니다. 셸 API로 핸들러를 자기 프로세스에 불러 여러 스레드에서 동시에 부르는 앱에서는 동시 요청 수만큼 늘어납니다.
- 화면 비율은 시퀀스 디스플레이 확장의 표시 영역이 화면 전체를 정확히 4:3이나 16:9로 만들 때만 그 영역 기준으로
  계산합니다. DVD의 팬 앤 스캔 영역(720 폭 영상의 540 폭 창)처럼 다른 용도로 쓰인 표시 영역에 맞추면 16:9 영상이
  2.37:1로 늘어나기 때문이며, ffmpeg도 같은 규칙을 씁니다.
- 검은 띠는 위아래나 좌우에 짝으로 있을 때만 잘라 냅니다. 두께가 많이 다르거나 한쪽이 화면의 4분의 1에 닿으면 얇은
  쪽 두께만큼만 양쪽에서 자르고, 양쪽 모두 4분의 1에 닿으면 자르지 않습니다. 한쪽 가장자리만 어두운 장면(밤하늘,
  어두운 벽)이나 검은 배경이 화면의 4분의 1 이상을 둘러싼 로고를 띠로 오인하지 않기 위해서입니다. 다만 그보다 좁은
  검은 여백에 둘러싸인 로고나 자막 화면은 여전히 그 부분만 잘려 나올 수 있으며, 그런 화면은 영화 앞부분이나 끝부분에
  많으므로 샘플 지점은 25%에서 시작하고 처음 지점은 마지막에 봅니다.
- 디코더는 세 가지 방법으로 검증합니다. `tests/mpeg2_oracle.rs`는 ffmpeg로 여러 설정(인트라 VLC 표, 대체 스캔, 비선형 양자화,
  DC 정밀도, 인터레이스, 여러 해상도, MPEG-1)의 스트림을 만들어 ffmpeg의 디코딩 결과와 비교합니다.
  `tests/vlc_crosscheck.rs`는 디코더와 별도로 표준 부록 B의 VLC 표를 옮겨 적고, 모든 코드워드를 담은 스트림을 만들어
  ffmpeg와 이 디코더가 같은 결과를 내는지 비교합니다. 단위 테스트는 무작위로 손상한 스트림이 패닉 없이 처리되는지 봅니다.
  ffmpeg가 PATH에 없으면 ffmpeg 비교 테스트는 건너뜁니다.
- `tests/dvd.rs`는 합성 DVD 이미지로 본편 선택, 어두운 장면 건너뛰기, 검은 띠 자르기, 재킷 그림 우선순위, 스크램블된 타이틀,
  읽기 상한과 함께, 디코딩할 수 없는 그림이 빽빽한 VOB, VOB 끝에 걸친 마지막 그림, 타이틀 세트가 70개를 넘는 디스크,
  실패한 타이틀 다음의 메뉴 대체 경로를 검사합니다. IFO 메뉴 표를 담은 합성 디스크로 루트 메뉴와 타이틀 메뉴 찾기,
  움직이는 메뉴의 마지막 VOBU, 손상된 IFO 대신 백업 읽기, 어두운 메뉴 대신 본편 장면, VOB 밖을 가리키는 메뉴 위치,
  무작위로 손상한 IFO도 검사합니다. 테스트용 IFO는 libdvdread가 읽는 배치(명령 표, 프로그램 맵, 셀 재생 표, 셀 위치
  표를 각자의 오프셋으로 찾는 구조)대로 만들며, 라우터 PGC, 타이틀 메뉴의 `JumpSS`, 인트로 셀이 있는 메뉴, 첫 언어
  단위의 잘못된 셀 위치도 검사합니다.
- `tests/bluray.rs`는 합성 Blu-ray 이미지(소스 패킷으로 다중화한 클립과 EP_map을 담은 클립 정보 파일)로 본편 클립 선택,
  아트워크 우선순위, 어두운 장면 건너뛰기, AACS 암호화, 3D 종속 뷰, 백업 클립 정보, 크기 상한이 없는 엔트리, DVD와 Blu-ray가
  함께 있는 디스크, 엉뚱한 곳을 가리키는 EP_map과 무작위로 손상한 클립을 검사합니다. Windows에서는 I_PCM 매크로블록으로
  직접 만든 H.264(프레임, 필드 쌍, I 프레임 크기를 줄여 적은 엔트리)와 Windows 인코더로 만든 HEVC 1080p/2160p, VC-1
  키 프레임(`tests/data`)을 실제 디코더로 풀어 결과 화면과 UHD 축소, HDR 톤 매핑, 읽기 범위 확장을 확인하며, 디코더가
  없는 시스템에서는 건너뜁니다. `src/nal.rs`의 단위 테스트는 잘라 낸 크기 뒤에 숨긴 큰 부호화 크기, 첫 슬라이스 뒤의
  SPS, 키 프레임이 아닌 그림, 금지 비트, VC-1 진입점의 부호화 크기를 검사합니다.
- Blu-ray 메뉴는 `tests/support/bd_writer.rs`가 libbluray의 파서 배치대로 만든 탐색 파일과 IG 세그먼트로 검사합니다.
  다루는 경우는 다음과 같습니다.
  - 탐색: 레지스터에 든 플레이리스트 번호, `PlayPLatPlayItem`으로 인트로 다음 재생 항목부터 시작하는 메뉴,
    `SetButtonPage`로 고른 버튼(호출한 객체에서 고른 버튼은 돌아오면 되돌립니다), 백업 탐색 파일, BD-J의 autostart
    플레이리스트
  - 메뉴로 보지 않는 경우: 버튼이 없는 인트로, 팝업 메뉴가 딸린 본편(세 개가 앞서 나와도 메뉴까지 시도합니다)
  - 재생 항목: 한 클립의 GOP 중간에서 시작하는 재생 항목과 GOP 하나보다 짧은 재생 항목, IN 시각 이전의 그림, OUT 시각
    밖의 그림, 진입점보다 앞에 다중화되고 그 앞에 이전 시각의 팝업 디스플레이 세트가 있는 메뉴 그래픽, 페이드 인으로
    시작하는 움직이는 메뉴의 중간 위치, 그림 하나뿐인 정지 메뉴(MPEG-2, H.264)
  - 대체 경로와 비용: 어두운 메뉴 대신 본편 장면(느린 원본에서 메뉴 단계가 시간을 다 쓰고 본편의 첫 지점이 깨져
    있어도 마찬가지), 디스플레이 세트가 끝나면 멈추는 IG 읽기, 서브 패스의 IG, 암호화된 메뉴, 키 프레임 안에서 잘린
    클립(MPEG-2는 정렬 단위 경계와 그 밖, H.264), 무작위로 손상한 탐색 파일과 IG

  ffmpeg가 libbluray와 함께 빌드되어 있으면 같은 합성 디스크를 `bluray:` 프로토콜로 열어, libbluray가 탐색 파일에
  불만 없이 메뉴와 본편 플레이리스트를 재생하는지 확인합니다. IG의 팔레트와 런 길이 부호는 자막(PG) 스트림과
  같으므로, 같은 팔레트와 그림을 PG 자막으로 만들어 ffmpeg의 디코딩 결과와 픽셀 단위로 비교합니다(차이 1 이하).
  `src/igs.rs`의 단위 테스트는 libbluray의 선택 버튼 규칙, 애니메이션이 자리 잡은 모습, 색 행렬 변환, 그림 세그먼트 59만 개와
  버튼 6만 5천 개를 넣은 조작된 스트림의 비용을 검사합니다.

## 등록되는 레지스트리 키

`HKCU\Software\Classes` 또는 `HKLM\Software\Classes` 아래에 다음 키가 만들어집니다.

- `CLSID\{C767266A-4032-4099-9A92-F91D1FE98122}\InprocServer32` : DLL 경로, `ThreadingModel=Apartment`
- `.iso\ShellEx\{E357FCCD-A995-4576-B01F-234630154E96}` : 위 CLSID

시스템 전체 설치일 때는 `HKLM\...\Shell Extensions\Approved`에도 CLSID를 추가합니다. 어느 범위에서도
`DisableProcessIsolation`은 기록하지 않으므로 핸들러는 격리된 대리 프로세스에서 실행됩니다. 이전 버전이 현재 사용자
설치에 남긴 `DisableProcessIsolation=1`은 다시 설치할 때 지웁니다.

같은 범위에 다른 프로그램의 `.iso` 썸네일 핸들러가 이미 등록되어 있었다면 그 CLSID를 위 CLSID 키의
`PreviousThumbnailHandler.iso` 값에 저장해 두었다가, 등록을 해제할 때 원래대로 되돌립니다.

## 테스트 이미지 만들기

실제 Blu-ray나 DVD 이미지가 없어도 Windows에 내장된 IMAPI2로 시험용 이미지를 만들 수 있습니다.

```bash
powershell -ExecutionPolicy Bypass -File scripts\make-test-isos.ps1 -OutDir C:\temp\test-isos
```

UDF 2.50(메타데이터 파티션), UDF 2.01, UDF 1.02, ISO 9660 + Joliet + UDF 브리지, Joliet 전용, ISO 9660 전용,
TN 폴더만 있는 이미지, 아트워크가 없는 이미지, 루트 커버만 있는 이미지 등 Blu-ray와 데이터 디스크 10종이 생성됩니다.
ffmpeg가 PATH에 있으면 ffmpeg의 DVD 다중화기(muxer)로 만든 실제 MPEG-2 프로그램 스트림을 담은 DVD-Video 이미지 5종도 만듭니다.
UDF 1.02 + ISO 9660 브리지, UDF 전용, ISO 9660 전용, 재킷 그림이 있는 이미지, PAL 16:9 이미지입니다. 본편은 두 VOB로
나뉘어 있고, 첫 샘플 지점(25%)은 검은 화면이며, NTSC 이미지의 화면에는 위아래 검은 띠가 있습니다.

## 제한 사항

- 스페어러블 파티션의 스페어링 테이블은 무시합니다. 결함 섹터가 재배치된 디스크 이미지는 드물기 때문입니다.
- 메뉴 명령은 `LinkPGCN`과 `JumpSS`(타이틀 메뉴에서 타이틀 세트 루트 메뉴나 비디오 매니저 PGC로 가는 경우)만 따라가며,
  조건부 명령은 조건과 무관하게 나열된 순서대로 시도합니다. 레지스터 값으로 메뉴를 고르는 복잡한 내비게이션은 실제
  플레이어와 다른 메뉴를 고를 수 있습니다.
- IFO 파일에서는 메뉴 표만 읽고 타이틀 표는 해석하지 않으므로, 본편은 VOB 데이터가 가장 많은 타이틀 세트로 봅니다.
  가짜 타이틀을 넣어 복사를 방해하는 일부 디스크에서는 본편이 아닌 타이틀 세트의 메뉴나 영상이 선택될 수 있습니다.
- 메뉴 화면은 배경 영상만 디코딩합니다. 메뉴 버튼과 글자를 서브픽처 오버레이로 그리는 디스크에서는 버튼이 빠진
  배경 그림이 썸네일이 됩니다.
- CSS로 암호화된 상태 그대로 만든 DVD 이미지와 AACS로 암호화된 상태 그대로 만든 Blu-ray 이미지는 영상 장면을 만들지
  못합니다. 복호화는 하지 않습니다.
- 필드 단위로 부호화된 I 프레임은 첫 필드만 디코딩해 줄을 두 배로 늘립니다(DVD와 Blu-ray의 MPEG-2, H.264 모두).
  썸네일 크기에서는 차이가 거의 없고, 두 필드를 엮을 때 생기는 빗살무늬도 없습니다.
- Blu-ray의 H.264와 VC-1은 Windows 기본 디코더로 풉니다(미디어 기능 팩이 없는 N 에디션 제외). HEVC(UHD Blu-ray)는
  Microsoft Store의 "HEVC 비디오 확장"이 설치되어 있어야 하며, 없으면 그런 디스크는 아트워크가 없을 때 기본 아이콘으로
  보입니다. 디코더가 없는 코덱의 클립은 영상을 읽지 않고 건너뜁니다.
- Blu-ray 메뉴는 HDMV 메뉴만 화면 그대로 재현합니다. 대부분의 할리우드 디스크가 쓰는 BD-J 메뉴는 자바 코드가 그리므로
  BD-J 객체가 스스로 시작하는 플레이리스트가 있을 때만 그 배경 영상을 쓰고, 없으면 본편 장면을 씁니다.
- HDMV 메뉴는 첫 페이지만 그리며, 페이지 효과(나타나는 효과)와 자동 실행 버튼의 활성화 모습은 그리지 않습니다. 서브
  패스에 따로 담긴 IG는 그리지 않고 배경만 씁니다. 명령은 실행하지 않고 살펴보기만 하므로, 레지스터 값에 따라 메뉴를
  고르는 디스크에서는 실제 플레이어와 다른 플레이리스트를 먼저 고를 수 있습니다. 클립에 시간 기준(STC)이 여러 개
  있으면 재생 항목의 STC를 가리지 않고 시각만으로 진입점을 고릅니다.
- Blu-ray 본편은 가장 큰 클립으로 봅니다. 부록 영상이 본편보다 큰 디스크(라이브 공연 디스크의 특전 영상 등)에서는 그
  부록의 장면이 썸네일이 됩니다. 3D 디스크는 기본(왼쪽 눈) 뷰를, Dolby Vision은 기본 계층만 씁니다. HDR 톤 매핑은
  스트림의 마스터링 메타데이터를 읽지 않고 최대 밝기를 1000 cd/m²로 가정합니다.
- MPEG-2 4:2:2/4:4:4와 스케일러블 스트림은 지원하지 않습니다. DVD-Video에는 쓰이지 않는 형식입니다.
- HD DVD와 Video CD 이미지는 지원하지 않습니다.
- `.iso` 확장자에만 연결됩니다. 다른 확장자에도 붙이려면 `src/registry.rs`의 `EXTENSIONS` 목록에 추가하고 다시 빌드하면 됩니다.
